# Small cases, then the pattern

Many problems that look like they need a long computation are settled by a short pattern. Use this procedure when the question involves a general n, a large parameter, or a count.

1. **Restate the target.** One line: the quantity asked for and the parameter it depends on.

2. **Work the smallest cases exactly.** Take the two to four smallest admissible values of the parameter and compute the answer for each completely and carefully. Keep these cases short; they are data, not the solution.

3. **Name the pattern.** From the small cases, write a precise conjecture: a formula, a recurrence, a period, or a structural statement (which configuration is extremal, which objects survive).

4. **Test it on one more case** that you did not use to form it. If it fails, revise the conjecture before going further.

5. **Explain why it holds.** Give the short reason: an induction step, a bijection, an invariant, a telescoping identity, or the general derivation the small cases suggested. Do not substitute a long enumeration for this step.

6. **Apply it to the actual parameter** of the question, with exact arithmetic, and check the size of the result is plausible.

7. **If the question is not of this kind**, solve it directly by the shortest route you can find. If answer options are listed you may use them to check; if none are listed, do not refer to options.

8. **Always finish** with the answer line in the form the question asks.
